Introduction

disensa simulates how opinions change in a community of agents connected by a network. The same experiment can run with classic numeric rules or with LLM agents that exchange messages, each possibly driven by a different model.

Each agent holds an opinion on a single statement, a number on \([-2, 2]\) from strongly against to strongly in favour. At every step agents interact with their neighbours and update their opinion. In a classic An agent-based model (ABM) simulates a system as many individual agents, each following simple rules. The behaviour of the whole is not specified anywhere: it emerges from the interactions. the update is an equation: an agent moves towards the average opinion of its neighbours (DeGroot), or only of those close enough to its own (bounded confidence). These rules are transparent and fast, but they reduce every interaction to a number.

LLM agents replace the equation with language. Each agent reads the messages its neighbours shared, reasons about them, and replies with a new opinion, a new message and an updated memory.

Two features set disensa apart. The first is model diversity: LLM-agent simulations usually run every agent on the same model (e.g. Wang et al., 2025), so agents differ only in their prompt while the reasoning underneath is identical. Here different agents can run on different models, each bringing its own tendencies and susceptibility to persuasion. The second is individual-level inspection: every reply is saved with its reasoning and memory, so a run can be followed agent by agent, showing not only where opinions end up but why each agent moved.

Both kinds of agents share the same engine, networks and metrics, so a numeric run and an LLM run of the same setup can be compared directly.

Quick start gets a first run going and How a run works describes the loop. The sections after that cover each part of a run in turn: the network, the numeric and LLM agents, the initial opinions, the metrics, and the files a run produces.

Quick start

disensa runs on your own computer. Numeric runs need nothing else. LLM runs also need Ollama, a free program that runs open-weight language models locally, so no account, API key or payment is involved.

  1. Install disensa (Python 3.11 or newer): pip install disensa, or uv tool install disensa.
  2. Install Ollama from ollama.com/download. Nothing else to set up: disensa starts Ollama when it needs it and stops it again when it closes.
  3. Open the lab with disensa app. It opens in the browser at http://127.0.0.1:8765.
  4. Get a model. In the Topic and models step of a new LLM run, download one of the suggested models with one click, or see Local models below to use the terminal.
  5. Run. Go through the remaining steps and start the run. It appears under Previous runs and can be followed step by step while it goes.

Local models

Any model from the Ollama library can drive agents. Download it once from a terminal, then check that it answers:

ollama pull llama3.2:3b
disensa ping ollama_chat/llama3.2:3b

Installed models appear in the lab’s model list. In a config file a model is written ollama_chat/<name>, e.g. ollama_chat/qwen3:4b (see Models). A model has to fit in memory while it runs, and its download size is a rough guide to how much it needs: models of 3–4B parameters (2–3 GB) run comfortably on a laptop with 16 GB, larger ones need more memory or a GPU.

Without the lab, a run can be started from a config file: disensa run configs/quick.yaml. This is also how disensa runs on a server, such as a university computing cluster: run the configs there and copy the run folders back into runs/ to open them in the lab.

Running on a vLLM server (INDACO)

On a GPU cluster such as INDACO the models are served by vLLM instead of Ollama. vLLM speaks the OpenAI request format, but a model is written hosted_vllm/<model> with api_base: http://<host>:8000/v1, not openai/<model>: LiteLLM’s openai/ connector refuses to send a request without an OpenAI API key, so every call would fail and the run would look like a run of perfectly stubborn agents. disensa stops such a config before it runs. configs/indaco_example.yaml is a complete example. The connector can be tried on a Mac against Ollama’s OpenAI-compatible endpoint:

disensa ping hosted_vllm/llama3.2:3b --api-base http://localhost:11434/v1

The same model name on Ollama and on vLLM is not the same model: Ollama usually serves 4-bit quantized weights, vLLM the full ones. Never mix runs from the two inside one comparison.

How a run works

A run is one simulation: a group of agents, linked by a network, each holding an opinion on the same statement. Time moves in rounds called steps. At every step each agent looks at what its neighbours think and updates its own opinion. Everything about a run is set in a config file: how many agents there are, how they are linked, how many steps to run, and what kind of agents to use.

Every run goes through two phases. The setup builds the network and gives every agent a starting opinion. The loop then runs one step after another, as many as the config asks for (steps, default 10), and saves the opinions after each one.

Agents come in two kinds, and each run uses one of them. Numeric agents update their opinion with a mathematical rule, such as moving towards the average of their neighbours. LLM agents each ask a language model: they read messages from their neighbours and decide on a new opinion. The kind is chosen in the config (dynamics.type), and each kind brings its own settings: a rule and its parameters for numeric agents, the statement and the models for LLM agents. The kind only changes how an agent updates its opinion inside a step. The network, the starting opinions, the loop and what gets saved work the same way for both, so runs of the two kinds can be compared directly.

Setup

  1. Read the config. The file is checked before anything runs: a missing or out-of-range parameter stops the run with an error. The seed fixes the world (network, starting opinions, model placement) and replicate the random draws of the dynamics, so the same config always gives the same run (see Seeds and replicates).
  2. Build the network. Agents are its nodes, numbered \(0\) to \(N-1\), and an agent only ever interacts with its neighbours. The network is redrawn until it is connected. See Network topologies.
  3. Draw the initial opinions, one per agent. Together they are written \(x(0)\), the opinions at step 0; in general \(x(t)\) are the opinions after step \(t\). See Initial opinions.
  4. Prepare the agents. Numeric agents need no further setup. With LLM agents, two more things happen. First, every agent is given a model: each model gets the share of agents set by its weight, placed at random on the network. Then every agent writes a first message stating its initial opinion. These are the messages the others will read at step 1.

Seeds and replicates

Every random draw in a run comes from two numbers. The seed fixes the world: the network, the starting opinions and which agent gets which model. The replicate (default \(0\)) fixes the dynamics: which neighbours each agent hears at each step, and the sampling seed sent with every model call.

This split gives the two comparisons the experiments need. Same seed, different dynamics: an LLM run and a numeric run with the same seed start from exactly the same network and opinions, so the numeric rules are baselines for that very LLM run. Same seed, different replicate: two LLM runs on the same world differ only in the dynamics’ own randomness, so how much their outcomes differ measures how much of an outcome is chance rather than the world. Numeric rules are deterministic and ignore replicate; setting it on a numeric run gives a warning. A run with a replicate other than \(0\) has _r<replicate> at the end of its folder name.

Each draw has its own random stream, derived from the two numbers with NumPy’s SeedSequence (seeding.py), so no two draws share random numbers. meta.json records "seeding": 2. Runs made before disensa 0.3 used a single stream for opinions and interactions, have no seeding key, and cannot be reproduced exactly with the current code.

One step

At step \(t\), every agent computes its new opinion from the state at step \(t-1\): its own opinion and what its neighbours held or said. Updates are Synchronous update: every agent works from the same snapshot, the state at step \(t-1\), and all new opinions replace the old ones at once. In an asynchronous update agents would go one at a time, each seeing the changes made before it, so the order in which they go would matter.: no agent sees another’s step-\(t\) opinion until the step is over, so the order in which agents are processed never matters. How an agent turns what it sees into a new opinion depends on its kind:

Numeric agents

Every agent applies the same equation to its own opinion and its neighbours’ opinions at \(t-1\). The whole step is one matrix operation on the opinion vector, with no randomness, so it takes no time. The three rules are in Numeric algorithms.

LLM agents

Every agent reads the messages of a few neighbours, reasons about them with its model, and replies with a new opinion, a new message and an updated memory. One step is one model call per agent. How this works is explained in LLM agents.

Then, for both kinds of agents, the step ends the same way. Opinions are kept on the scale from \(-2\) to \(+2\): if a language model replies with a value outside it, say \(3\), it is set to the nearest end, \(+2\). Then the metrics are computed, and the step is written to disk. A run with steps: 10 records 11 states: step 0 and ten updates.

At the end

Each run gets its own folder, runs/<timestamp>_<name>_s<seed>/ (with _r<replicate> for a replicate other than \(0\)), filled step by step while the run goes: if a run is stopped, every finished step is kept. When the loop is done the run is marked as finished, with its duration and, for LLM runs, the number of model calls. What each file holds is in Run files; how to follow a run in the lab, agent by agent, is in Reading a run.

Reproducibility. A numeric run is fully determined by its config. An LLM run is too, once its replies are cached: every reply is stored on disk under its exact request, so running the same config again replays the same replies instead of calling the models, and the run comes out identical.

Network topologies

Each agent is a node in the network, with its own independent state. In an LLM run, different nodes can be driven by different models (e.g. Llama, Qwen, Gemma); see LLM agents for how models are assigned to nodes. A link between two nodes means those agents interact. Networks are undirected and unweighted: if \(i\) is linked to \(j\), then \(j\) is linked to \(i\), and every link counts the same. Three classic models are available to generate the network:

Random (Erdős–Rényi)

Every pair of nodes is linked with the same probability \(p\). Because links are placed purely at random, clustering is low and there are no hubs. Clustering means an agent's neighbours are also linked to each other, forming triangles: tight groups where everyone knows everyone. Hubs are single agents with far more links than average. The two are independent: a network can have one without the other.

Small-world (Watts–Strogatz)

A ring where each agent links to its \(k\) nearest neighbours, and a share \(\beta\) of the links are rewired at random. Neighbours share neighbours, so clustering is high, while the rewired links act as shortcuts that keep paths short. Tight local groups, no hubs.

Scale-free (Barabási–Albert)

A few hubs hold many links while most agents have only a few: An agent's degree \(k_i\) is its number of links, i.e. how many neighbours it has. The degree distribution \(p_k\) is the share of agents with exactly \(k\) links. follow a \(p_k \propto k^{-\gamma}\): the share of agents with \(k\) links falls off slowly, as a power of \(k\), not exponentially as in a random network. Highly connected agents stay rare but not vanishingly so, which is why hubs appear. Here \(\gamma = 3\)., with no typical value. Hubs arise from The better connected an agent is, the more likely it is to gain new links, so the rich get richer. An agent's chance of receiving a link is proportional to its degree \(k_i\).. Clustering is low; \(m\) sets the density (average degree \(2m\)).

Each model isolates one structural feature while keeping paths short, so they can be compared one feature at a time:

  • Scale-free adds hubs: do a few highly connected agents dominate, spreading opinions fast and pulling others toward them?

Describing a network

A network has \(N\) nodes (here, agents) and \(L\) links. It is stored as the adjacency matrix \(A\), with \(A_{ij} = 1\) if \(i\) and \(j\) are linked and \(0\) otherwise; for an undirected network \(A\) is symmetric.

QuantityDefinitionMeaning
Degree \(k_i\)\(k_i = \sum_j A_{ij}\)Number of neighbours of \(i\).
Average degree \(\langle k \rangle\)\(\langle k \rangle = 2L / N\)Average number of neighbours per agent. The factor 2 is there because each link counts toward the degree of both its ends.
Degree distribution \(p_k\)\(p_k = N_k / N\)Share of nodes with exactly \(k\) links. The main property separating the three models.
Distance \(d_{ij}\)links on the shortest path from \(i\) to \(j\)Averaged over all pairs it gives the average path length \(\langle d \rangle\); the largest is called the diameter.
Clustering coefficient \(C_i\)\(C_i = \dfrac{2L_i}{k_i(k_i - 1)}\)\(L_i\) is the number of links among \(i\)'s neighbours: the share of \(i\)'s neighbours that are also linked to each other. Averaged over nodes it gives \(\langle C \rangle\).

A network is connected when there is a path between every pair of nodes; otherwise it splits into components. Real networks are sparse: \(L\) is far below the maximum possible number of links, which for an undirected network is \(N(N-1)/2\), every pair linked once.

Random (Erdős–Rényi)

Every pair of the \(N\) nodes is linked independently with probability \(p\).

\[ \langle L \rangle = p\,\frac{N(N-1)}{2} \qquad \langle k \rangle = p\,(N-1) \]

Degrees. The degree distribution is binomial, and for sparse networks (\(\langle k \rangle \ll N\)) it is well approximated by a Poisson distribution, narrowly peaked around \(\langle k \rangle\). High degrees are exponentially rare, so there are no hubs: most agents have about the same number of neighbours.

\[ p_k = e^{-\langle k \rangle} \frac{\langle k \rangle^{k}}{k!} \]

Connectedness. As \(\langle k \rangle\) grows the network goes through distinct regimes: below \(\langle k \rangle = 1\) it is a set of small fragments; above \(1\) a giant component appears; around \(\langle k \rangle = \ln N\) the whole network becomes connected. The transition is sharp only for very large \(N\): with 50 agents it is gradual (see Choosing \(p\) below).

Small world. Distances are short and grow only logarithmically with size:

\[ \langle d \rangle \approx \frac{\ln N}{\ln \langle k \rangle} \]

Clustering. Two neighbours of a node are linked with the same probability \(p\) as any other pair, so clustering is low, independent of degree, and shrinks as the network grows:

\[ \langle C \rangle = p = \frac{\langle k \rangle}{N-1} \approx \frac{\langle k \rangle}{N} \]

Real networks have far more clustering and far broader degree distributions than this model predicts. It is used as the null model: what a network looks like when links are placed purely at random.

Choosing \(p\). The network becomes connected around \(\langle k \rangle = \ln N\). With 50 agents \(\ln 50 \approx 3.9\), so \(p \approx 3.9 / 49 \approx 0.08\). That is the threshold, not a safe value: at \(p = 0.08\) only about 40% of draws are connected, and the rest get redrawn (see below). With \(p \approx 0.12\) (\(\langle k \rangle \approx 6\)), over 90% of draws are connected.

Small-world (Watts–Strogatz)

Real networks are both clustered (your neighbours know each other) and The small-world property: the average distance between two nodes grows only like \(\ln N\), so even in a huge network anyone is a few steps from anyone (“six degrees of separation”). Random networks already have it: in \(d\) steps a node reaches about \(\langle k \rangle^d\) others, so a few steps cover the whole network. Network Science, ch. 3 → (short paths between anyone). A Ring, \(k = 4\)Square gridA regular lattice places nodes on a regular pattern and links each only to its nearest neighbours, so every node looks the same. It has high clustering but long paths: distances grow like \(N\) on a ring or \(\sqrt{N}\) on a grid, not \(\ln N\). has the first but not the second; a random network has the second but not the first. The Watts–Strogatz model interpolates between the two:

  1. Start from a ring where each node is linked to its \(k\) nearest neighbours.
  2. Rewire each link with probability \(\beta\), moving one end to a randomly chosen node.
  • \(\beta = 0\): the ring lattice. High clustering, long paths.
  • \(\beta = 1\): essentially a random network. Low clustering, short paths.
  • Small \(\beta\) (for example \(0.01\)–\(0.1\)): a few rewired links act as shortcuts across the ring, so \(\langle d \rangle\) drops sharply, while almost all local triangles survive and clustering stays high. This is the small-world regime.

Every node starts with degree \(k\) and rewiring moves only one end of a link, so degrees stay close to \(k\): \(\langle k \rangle = k\) and there are no hubs.

Clustering. On the ring, \(C(0) = \dfrac{3(k-2)}{4(k-1)}\): \(0.5\) for \(k = 4\), \(0.6\) for \(k = 6\), and \(0\) for \(k = 2\), where an agent's two neighbours are never linked. A triangle survives only if none of its three links is rewired, so clustering falls as

\[ C(\beta) \approx C(0)\,(1-\beta)^3 \]

At \(\beta = 0.1\) about 73% of the ring's clustering is left; past \(\beta \approx 0.2\) less than half is, and the network looks increasingly random.

Scale-free (Barabási–Albert)

This topology introduces the scale-free property: as in many real networks, the degree distribution follows a power law rather than a Poisson distribution:

\[ p_k \sim k^{-\gamma} \]

A power law decays slowly, so very high degrees are rare but not negligible: the network has hubs, nodes with far more links than average. \(\langle k \rangle\) is then a poor description of a typical node.

The degree exponent. \(\gamma\) is not fixed by the definition, but it The shares \(p_k = C\,k^{-\gamma}\) must add up to \(1\), so the sum \(\sum_{k \ge 1} k^{-\gamma}\) has to be finite. It is only for \(\gamma > 1\). At \(\gamma = 1\) it is the harmonic series \(1 + \tfrac12 + \tfrac13 + \dots\), which grows forever, and smaller \(\gamma\) only makes it grow faster. With an infinite sum, no constant \(C\) can make the shares add up to \(1\). for \(p_k\) to be a valid distribution, and its value decides how the network behaves. Most real networks have \(2 < \gamma < 3\); Barabási–Albert always gives \(\gamma = 3\).

  • \(1 < \gamma < 2\): the largest hub would need more links than there are nodes, so large networks without repeated links cannot have it.
  • \(2 < \gamma < 3\): hubs are large enough to dominate. Distances are tiny, \(\langle d \rangle \sim \ln \ln N\): an Hubs act as shortcuts: most paths pass through one, and hubs are linked to each other, so distances grow like \(\ln \ln N\), even more slowly than the \(\ln N\) of a random network. With a million nodes, \(\ln N \approx 14\) but \(\ln \ln N \approx 2.6\). Network Science, ch. 4 →.
  • \(\gamma = 3\): the boundary case, \(\langle d \rangle \sim \ln N / \ln \ln N\), still shorter than in a random network.
  • \(\gamma > 3\): hubs are too small to matter and the network behaves much like a random one, \(\langle d \rangle \sim \ln N\).

Barabási–Albert produces a power-law degree distribution with two mechanisms:

  1. Growth. Start from a few nodes and add one node at a time, each with \(m\) links.
  2. Preferential attachment. Each new link goes to existing node \(i\) with probability proportional to its degree:
\[ \Pi(k_i) = \frac{k_i}{\sum_j k_j} \]

Well-connected nodes get more new links, so they become better connected (“the rich get richer”). A node that arrived at time \(t_i\) has, at time \(t\),

\[ \langle k_i(t) \rangle \approx m \left( \frac{t}{t_i} \right)^{1/2} \]

so the oldest nodes become the hubs (first-mover advantage). The resulting degree distribution is a power law with \(\gamma = 3\), whatever the value of \(m\):

\[ p_k \approx 2m(m+1)\,k^{-3} \qquad \langle k \rangle \approx 2m \]

Both mechanisms are needed. Growth without preferential attachment gives an exponential degree distribution (no hubs). Preferential attachment without growth gives no stationary power law: the network eventually becomes fully connected.

Clustering is low, \(\langle C \rangle \sim (\ln N)^2 / N\). That is higher than in a random network of the same size, but it still vanishes as \(N\) grows.

In disensa

Networks are built with NetworkX (network.py). Every network is seeded, so the same seed gives the same network, and always connected: a disconnected draw is redrawn with a new seed derived from the original, up to 100 times. This matters for two reasons. Opinions only travel along links, so separate parts of a network would never influence each other and would evolve as independent simulations. And only Erdős–Rényi can split (Barabási–Albert is connected by construction, and Watts–Strogatz is built connected), so allowing it would add a difference between topologies that has nothing to do with their structure. All topologies take n, the number of agents (default 50).

Numeric algorithms

Numeric algorithms are the classic way to model how agents (the nodes of the network) update their opinions. Where an LLM agent changes its opinion by prompting a language model, a numeric agent applies an algebraic equation that computes its new opinion deterministically from its own opinion and those of its neighbours. disensa has three algorithms, all in dynamics/numeric.py: DeGroot is plain averaging, and the other two each add one mechanism to it, a similarity filter (bounded confidence) or stubbornness (Friedkin–Johnsen). Like LLM agents, every agent reads the opinions of step \(t-1\) and all updates apply together, using the adjacency matrix \(A\) from Describing a network. All three belong to the family of Assimilative influence: when an agent updates, its opinion moves towards the opinions of the neighbours it listens to, never away from them. Models where opinions can also be pushed apart (repulsion) are a separate family, not implemented here. See Flache et al. (2017), §2. models.

DeGroot (averaging)

At each step, every agent replaces its opinion with the average of its own opinion and those of its neighbours \(N(i)\) at the previous step. Every opinion in the average counts the same: an agent with \(k_i\) neighbours averages \(k_i + 1\) values, its own included.

\[ x_i(t) = \frac{1}{k_i + 1} \sum_{j \in N(i) \cup \{i\}} x_j(t-1) \]

Matrix form. The same update can be written for all agents at once. Put every opinion in a column vector \(x(t) = (x_1(t), \dots, x_N(t))^\top\) and every weight in an \(N \times N\) matrix \(W\), where \(W_{ij}\) is how much agent \(i\) listens to agent \(j\) (in disensa, the same for itself and each of its neighbours). Then the whole step is one multiplication:

\[ x(t) = W\,x(t-1) \]

Element \(i\) of the resulting vector is \(\sum_j W_{ij}\, x_j(t-1)\), agent \(i\)’s new opinion: the same update as above. In disensa, \(W_{ij} = 1/(k_i + 1)\) if \(j\) is \(i\) itself or one of its neighbours, and \(0\) otherwise. With the adjacency matrix \(A\) and the identity matrix \(I\) (which links each agent to itself), that is

\[ W_{ij} = \frac{A_{ij} + I_{ij}}{k_i + 1} \]

Every entry of \(W\) is \(\ge 0\) and every row sums to \(1\): \(W\) is Row-stochastic matrix: a square matrix whose entries are all \(\ge 0\) and whose rows each sum to \(1\), \(\sum_j W_{ij} = 1\) for every \(i\). Each row is a set of weights, so multiplying a vector by it turns every entry into a weighted average of the vector’s entries.. That is what makes each new opinion a weighted average of the old ones. DeGroot’s general model allows any row-stochastic \(W\), so agents can weigh each other differently; disensa uses the equal weights above.

Example: one step on a path of three agents

Three agents on a path \(1 - 2 - 3\): agent 2 has two neighbours, agents 1 and 3 have one each. They start from \(x(0) = (-2,\ -1,\ 1.5)^\top\).

Build \(W\) from the network. The adjacency matrix \(A\) marks who is linked to whom; adding \(I\) puts a \(1\) on the diagonal, so each agent also counts itself:

\[ A + I = \begin{pmatrix} 0 & 1 & 0 \\ 1 & 0 & 1 \\ 0 & 1 & 0 \end{pmatrix} + \begin{pmatrix} 1 & 0 & 0 \\ 0 & 1 & 0 \\ 0 & 0 & 1 \end{pmatrix} = \begin{pmatrix} 1 & 1 & 0 \\ 1 & 1 & 1 \\ 0 & 1 & 1 \end{pmatrix} \]

Row \(i\) now has \(k_i + 1\) ones: one for each opinion agent \(i\) averages. Dividing each row by that count makes the row sum to \(1\):

\[ k + 1 = \begin{pmatrix} 2 \\ 3 \\ 2 \end{pmatrix} \quad\Longrightarrow\quad W = \begin{pmatrix} \frac12 & \frac12 & 0 \\[6pt] \frac13 & \frac13 & \frac13 \\[6pt] 0 & \frac12 & \frac12 \end{pmatrix} \]

One step is one multiplication:

\[ x(1) = W\,x(0) = \begin{pmatrix} \frac12 & \frac12 & 0 \\[6pt] \frac13 & \frac13 & \frac13 \\[6pt] 0 & \frac12 & \frac12 \end{pmatrix} \begin{pmatrix} -2 \\[6pt] -1 \\[6pt] 1.5 \end{pmatrix} = \begin{pmatrix} \tfrac{-2-1}{2} \\[6pt] \tfrac{-2-1+1.5}{3} \\[6pt] \tfrac{-1+1.5}{2} \end{pmatrix} = \begin{pmatrix} -1.5 \\[6pt] -0.5 \\[6pt] 0.25 \end{pmatrix} \]

Every agent moves towards its neighbours. Agent 2, in the middle, hears both sides; agents 1 and 3 only hear agent 2. The gap between the most extreme opinions halves, from \(3.5\) to \(1.75\), and keeps halving at every step as the three opinions approach the same value.

Where it goes. On a connected network, averaging converges to consensus: as the steps go on, all opinions approach the same value (DeGroot, 1974; Flache et al., 2017, §2). They get arbitrarily close but, in general, never become exactly equal: the gap between the highest and lowest opinion shrinks by a roughly constant factor every step (in the example above it halves). disensa networks are always connected, so a long enough DeGroot run always gets close to consensus. Because each update is an average, opinions also never leave the range of the initial ones.

The consensus value. The value they approach, \(x^\ast\), is a weighted average of the initial opinions \(x_i(0)\) of the agents \(i = 1, \dots, N\), with weights proportional to \(k_i + 1\):

\[ x^\ast = \sum_i w_i\, x_i(0), \qquad w_i = \frac{k_i + 1}{\sum_j (k_j + 1)} \]

The weights sum to \(1\). Well-connected agents are listened to by more agents, so they pull the consensus towards their own starting opinion; in a scale-free network, hubs get a visibly larger say. The reason is that the sum of opinions weighted by \(k_i + 1\) stays the same at every step, so at consensus it still equals its starting value. In the example, \(x^\ast = (2 \cdot (-2) + 3 \cdot (-1) + 2 \cdot 1.5) / 7 \approx -0.57\), not the plain average \(-0.5\): agent 2 has the most neighbours, so its opinion counts more.

That is also the model's limit. It cannot produce polarization or echo chambers, only consensus, which makes it the reference point: anything else a run shows comes from what the other rules add.

Bounded confidence

Agents only listen to neighbours whose opinion is already close to their own: within a confidence bound \(\varepsilon\). Neighbours further away are ignored. For agent \(i\), the neighbours it listens to, together with itself, form its Agent \(i\) itself plus the neighbours \(j\) with \(|x_i - x_j| \le \varepsilon\) at step \(t-1\). It changes every step as opinions move, so two agents can stop listening to each other once they drift apart, and start again if they come close. \(C_i(t-1) = \{\, j \in N(i) \cup \{i\} : |x_i(t-1) - x_j(t-1)| \le \varepsilon \,\}\), and the agent moves towards the average of that set, but only part of the way: it covers a fraction \(\mu\) of the distance between its opinion and that average. With \(\mu = 1\) it jumps straight to the average; with \(\mu = 0.5\) it goes halfway.

\[ x_i(t) = x_i(t-1) + \mu \left( \frac{1}{|C_i|} \sum_{j \in C_i} x_j(t-1) \;-\; x_i(t-1) \right) \]

If no neighbour is within \(\varepsilon\), the set holds only the agent itself, so it keeps its opinion.

  • \(\varepsilon\) (epsilon): how open-minded agents are. It decides the outcome.
  • \(\mu\) (mu, \(0 < \mu \le 1\)): how far an agent moves per step; \(\mu = 1\) is plain Hegselmann–Krause. It mainly affects the speed.

Two classic versions. Bounded confidence has two standard forms; disensa uses a variant that combines them:

ModelWho updatesUpdate
Deffuant et al. (2000)One random pair at a timeEach moves \(\mu\) towards the other, if within \(\varepsilon\).
Hegselmann–Krause (2002)Everyone at onceEach takes the plain average of all agents within \(\varepsilon\), itself included (\(\mu = 1\)), originally with everyone able to see everyone.
Inertial Hegselmann–Krause (Chazelle & Wang, 2017), used by disensaEveryone at onceAverages all agents within \(\varepsilon\), itself included, like Hegselmann–Krause, but moves only \(\mu\) of the way towards that average, like Deffuant. The original has no network (anyone within \(\varepsilon\) counts); in disensa only linked agents count.

Where it goes. If \(\varepsilon\) is large, everyone is eventually linked by chains of agents who listen to each other and opinions converge to consensus, as with DeGroot. If \(\varepsilon\) is small, the population splits into separate opinion clusters that no longer listen to each other; the smaller \(\varepsilon\), the more and smaller the clusters (Flache et al., 2017, §2). Hegselmann and Krause (2002, §4.1) describe three phases as \(\varepsilon\) grows:

  • Plurality: many opinions survive.
  • Polarization: two camps.
  • Consensus: everyone converges to one opinion.

On a network the bound is not the only obstacle: an agent can only be pulled by its own neighbours, so clusters also form where the network itself keeps groups apart.

As with DeGroot, every update is an average (for \(\mu \le 1\)), so opinions stay within the initial range: the model can split a population into camps, but not make it more extreme than its initial extremists (Flache et al., 2017, §2).

Large \(\varepsilon\). Opinions are at most \(4\) apart, so with \(\varepsilon \ge 4\) every neighbour is always in the confidence set; with \(\mu = 1\) the rule is then exactly DeGroot.

Friedkin–Johnsen (stubbornness)

Agents average with their neighbours, but never fully let go of where they started. Each agent keeps its initial opinion \(s_i = x_i(0)\) as its The innate opinion \(s_i\) is the view an agent holds on its own, before any influence; it never changes. What changes is the opinion it expresses, \(x_i(t)\), which mixes \(s_i\) with what its neighbours say. Friedkin and Johnsen call the pull of \(s_i\) the agent's prejudice or stubbornness. and mixes it with its neighbours' current opinions, as in Chitra & Musco (2020, eq. 1):

\[ x_i(t) = \frac{\lambda\, s_i + \sum_{j \in N(i)} x_j(t-1)}{\lambda + k_i} \]

The sum runs over agent \(i\)’s neighbours \(N(i)\), and \(k_i\) is its degree (how many neighbours it has).

\(\lambda\) (stubbornness) is how much the innate opinion weighs compared with one neighbour. Chitra & Musco use \(\lambda = 1\): the innate opinion counts as one extra neighbour. Since the sum over \(k_i\) neighbours is \(k_i\) times their average \(\bar{x}_{N(i)}(t-1)\), the update is a weighted average of the innate opinion and the neighbours’ average:

\[ x_i(t) = \frac{\lambda}{\lambda + k_i}\, s_i \;+\; \frac{k_i}{\lambda + k_i}\, \bar{x}_{N(i)}(t-1) \]

The more neighbours an agent has, the less weight its innate opinion gets, so well-connected agents are pulled harder by the group. In the original model (Friedkin & Johnsen, 1990) the weight on each agent’s innate opinion is a separate parameter, set freely per agent; here it follows from the degree.

Where it goes. Not to a common consensus. Every agent keeps being pulled back towards its own innate opinion \(s_i\), so each agent approaches its own equilibrium \(x_i^\ast\): the opinion at which the pull of its innate opinion and the pull of its neighbours’ average balance, so that it no longer changes from one step to the next. Neighbours end up closer than they started, but disagreement never disappears: large \(\lambda\) keeps agents near their innate opinions, small \(\lambda\) brings them close to consensus. Opinions stay within the initial range, as with the other two rules.

Computing the equilibrium. The equilibrium can be computed directly, without running the simulation, using the Graph Laplacian: the matrix \(L = D - A\), with each agent’s degree on the diagonal, \(-1\) for each link and \(0\) elsewhere, so every row sums to \(0\). It measures differences across links: \(L\,x\) is \(0\) for every agent exactly when all neighbours agree. \(L = D - A\). Here \(A\) is the adjacency matrix and \(D\) is the degree matrix: a diagonal matrix with each agent’s degree \(k_i\) on the diagonal and zeros elsewhere. Multiplied by the opinion vector \(x\), \(L\) gives each agent’s total difference from its neighbours: positive if it sits above them, negative if below. For agent \(i\), that is element \(i\) of the vector \(L\,x\), i.e. row \(i\) of \(L\) times \(x\):

\[ (L\,x)_i = k_i\, x_i - \sum_{j \in N(i)} x_j = \sum_{j \in N(i)} (x_i - x_j) \]

Row \(i\) of \(L\) has \(k_i\) on the diagonal, \(-1\) for each neighbour and \(0\) for everyone else, so non-neighbours drop out. The result is \(0\) when the agent sits exactly at its neighbours’ average.

At equilibrium opinions stop changing, so \(x_i(t) = x_i(t-1) = x_i^\ast\). Putting this into the update and rearranging gives, for every agent,

\[ \lambda\,(x_i^\ast - s_i) + (L\,x^\ast)_i = 0 \]

its distance from its innate opinion balances its distance from its neighbours. For all agents at once this is one linear system, solved for \(x^\ast\):

\[ (\lambda I + L)\, x^\ast = \lambda\, s \qquad\Longrightarrow\qquad x^\ast = \lambda\, (\lambda I + L)^{-1}\, s \]
Derivation, step by step
  1. At equilibrium nothing changes, \(x_i(t) = x_i(t-1) = x_i^\ast\), so every opinion in the update becomes \(x^\ast\):
    \[ x_i^\ast = \frac{\lambda\, s_i + \sum_{j \in N(i)} x_j^\ast}{\lambda + k_i} \]
  2. Multiply both sides by \(\lambda + k_i\):
    \[ \lambda\, x_i^\ast + k_i\, x_i^\ast = \lambda\, s_i + \sum_{j \in N(i)} x_j^\ast \]
  3. Move everything to the left and group. The first term is the agent’s distance from its innate opinion, the second its distance from its neighbours, and they cancel:
    \[ \underbrace{\lambda\,(x_i^\ast - s_i)}_{\text{from innate opinion}} \;+\; \underbrace{k_i\, x_i^\ast - \sum_{j \in N(i)} x_j^\ast}_{(L\,x^\ast)_i\text{, from neighbours}} = 0 \]

Stacking the equations for all agents gives \(\lambda\,(x^\ast - s) + L\,x^\ast = 0\), and since \(\lambda\, x^\ast = \lambda I\, x^\ast\) this is \((\lambda I + L)\, x^\ast = \lambda\, s\). \(\lambda I + L\) can be inverted because \(\lambda > 0\).

Example: the equilibrium on a path of three agents

The same path \(1 - 2 - 3\) as in the DeGroot example, with innate opinions \(s = x(0) = (-2,\ -1,\ 1.5)^\top\) and \(\lambda = 1\).

Build the Laplacian from the degrees and the links:

\[ L = D - A = \begin{pmatrix} 1 & 0 & 0 \\ 0 & 2 & 0 \\ 0 & 0 & 1 \end{pmatrix} - \begin{pmatrix} 0 & 1 & 0 \\ 1 & 0 & 1 \\ 0 & 1 & 0 \end{pmatrix} = \begin{pmatrix} 1 & -1 & 0 \\ -1 & 2 & -1 \\ 0 & -1 & 1 \end{pmatrix} \]

At the start, \(L\,s\) shows how far each agent sits from its neighbours: agent 1 is \(1\) below agent 2, agent 3 is \(2.5\) above agent 2, and agent 2 is pulled both ways:

\[ L\,s = \begin{pmatrix} 1 & -1 & 0 \\ -1 & 2 & -1 \\ 0 & -1 & 1 \end{pmatrix} \begin{pmatrix} -2 \\ -1 \\ 1.5 \end{pmatrix} = \begin{pmatrix} -1 \\ -1.5 \\ 2.5 \end{pmatrix} \]

The equilibrium solves \((\lambda I + L)\, x^\ast = \lambda\, s\). With \(\lambda = 1\), \(\lambda I + L\) adds \(1\) to each diagonal entry of \(L\), and \(\lambda\, s = s\):

\[ \lambda I + L = 1 \cdot \begin{pmatrix} 1 & 0 & 0 \\ 0 & 1 & 0 \\ 0 & 0 & 1 \end{pmatrix} + \begin{pmatrix} 1 & -1 & 0 \\ -1 & 2 & -1 \\ 0 & -1 & 1 \end{pmatrix} = \begin{pmatrix} 2 & -1 & 0 \\ -1 & 3 & -1 \\ 0 & -1 & 2 \end{pmatrix} \]
\[ \lambda\, s = 1 \cdot \begin{pmatrix} -2 \\ -1 \\ 1.5 \end{pmatrix} = \begin{pmatrix} -2 \\ -1 \\ 1.5 \end{pmatrix} \]

Solving:

\[ \begin{pmatrix} 2 & -1 & 0 \\ -1 & 3 & -1 \\ 0 & -1 & 2 \end{pmatrix}\, x^\ast = \begin{pmatrix} -2 \\ -1 \\ 1.5 \end{pmatrix} \qquad\Longrightarrow\qquad x^\ast = \begin{pmatrix} -1.3125 \\ -0.625 \\ 0.4375 \end{pmatrix} \]

Each agent settles at its own value, between its innate opinion and its neighbours. The gap between the most extreme opinions shrinks from \(3.5\) to \(1.75\) and stays there; DeGroot, on the same path, brings all three to \(-0.57\). Agent 1, for example, balances a pull of \(0.69\) back towards its innate \(-2\) against a pull of \(0.69\) towards agent 2.

LLM agents

An LLM agent replaces the update equation with a language model. Instead of computing a new opinion from numbers, it reads what a few of its neighbours said, reasons about it, and replies with a new opinion, a new message and an updated memory. Everything else in a run (the network, the initial opinions, the loop, the metrics) is the same as with numeric agents.

Agents in the same run can use different models: every agent is assigned a model, so one community can mix models from different labs, each reasoning in its own way. Agents are members of a community who exchange messages about a single statement; nothing in the prompts refers to a specific platform or medium. The code is in dynamics/llm_agent.py, and every prompt is in llm/prompts.py, quoted in full below.

What an agent is

Each agent is a node of the network with a model attached and three things that carry over from one step to the next:

Opinion

A number on \([-2, 2]\), exactly as for numeric agents. This is what the metrics measure.

Message

The last thing it said, 1–3 sentences. This is what its neighbours read at the next step.

Memory

A short summary of what it has heard and thought so far, which the agent rewrites itself at every step.

The model call is A language model remembers nothing between calls. Everything the agent “knows” at step \(t\) has to be written into the prompt of that call: its opinion, its memory and the messages it hears.: the agent only knows what is written in its prompt. Its identity is minimal: the system prompt calls it “Agent \(i\), a member of a community”, with no name, age or personality.

No personas. Wang et al. give each agent a gender, an age, an education level and Big Five personality traits; Chuang et al. add political leaning, ethnicity and occupation. disensa leaves them out on purpose: without personas, two agents that start from the same opinion can only differ because of their model, which is one of the effects under study.

Initial opinion and first message

An LLM agent does not choose its starting opinion: it is drawn from opinions.distribution, exactly as for numeric agents (see Initial opinions). The number is then put into words. It is rounded to the nearest integer and turned into one of five stance labels, and both the label and the exact value go into the prompt:

Opinion (rounded)\(-2\)\(-1\)\(0\)\(+1\)\(+2\)
Labelstrongly opposesomewhat opposeneutral / undecidedsomewhat supportstrongly support

At step 0 every agent writes a first message from that position, e.g. “You somewhat oppose this statement (your position: \(-0.8\) on a scale from \(-2\) to \(+2\))”. These first messages are what the agents hear at step 1. Step 0 does not change any opinion.

The starting opinion is given, not chosen. The model does not pick its own starting position. This keeps LLM and numeric runs comparable, since both start from the same opinions. The cost is that a model’s own leaning on the statement is hidden at the start, and can only show up later.

Interactions

At each step an agent interacts with a few of its neighbours: it hears the message each of them shared at step \(t-1\). How many is random, drawn every step between interactions.min and interactions.max (default \(1\) to \(5\)), and capped at the agent’s number of neighbours: an agent with 3 neighbours that draws 5 hears all 3. The neighbours are then picked uniformly at random: every neighbour is equally likely, whatever its opinion or degree. Both draws are new at every step and separate for each agent, so hearing is not mutual: agent \(i\) can hear \(j\) at a step without \(j\) hearing \(i\). A message from a neighbour reaches the agent as one line of the prompt: - Agent 7 said: "...".

This is a different kind of influence from the numeric rules. There, an agent sees the opinions of all its neighbours, every step. Here it sees the messages of some of them, and never their numbers: whatever a neighbour’s opinion is, only the words reach the agent. A hub can still hear only five others per step, but it is heard by many.

Updating the opinion

The prompt gives the agent its current position (label and value), its memory and its interactions, and asks it to reflect on them “as the person you are”: it may keep, soften, strengthen or change its position. It must reply with JSON holding four fields:

There is no update rule. Unlike the numeric algorithms, there are no parameters that shape the update: no confidence bound \(\varepsilon\), no step size \(\mu\), no stubbornness. The new opinion is whatever number the model reports. If LLM agents end up listening only to similar views (as in bounded confidence) or clinging to where they started (as in Friedkin–Johnsen), that behaviour comes from the model, not from the code.

Models

The models of a run are listed under dynamics.models. Each has a weight, and each model gets that share of the agents: three models with equal weight and 20 agents give \(7 + 7 + 6\). Shares are rounded so the counts always add up to \(N\) (Each model first gets the whole part of its exact share (\(20/3 = 6.67 \to 6\)). The agents left over go one each to the models with the largest fractional parts.). The agents are then placed on the network at random: the list of model labels is shuffled and handed out to the agents. The shuffle has its own random generator, fixed by the seed alone (see Seeds and replicates), so two runs with the same seed but different models have the same network, initial opinions and interactions; only the models differ.

A model is written as ollama_chat/<name>, e.g. ollama_chat/llama3.2:3b: ollama_chat says the model runs on Ollama, on the same computer as disensa, and the rest is the model’s name there. Only local models are used, so runs are free and no data leaves the machine. How to install and download models is in Local models. disensa sends every request through LiteLLM, a library that talks to model servers in a uniform way.

Each request also carries settings that are not part of the prompt. The Temperature \(T\): a model writes one token at a time, giving each candidate \(k\) a score \(z_k\) and drawing it with probability \(p_k \propto e^{z_k / T}\). As \(T \to 0\) the top token almost always wins; at \(T = 1\) the model’s own probabilities are used; above \(1\) unlikely tokens get through more often. (default \(0.7\)) sets how varied the replies are: low values give nearly the same reply to the same prompt, higher values more varied ones. top_p (default \(0.9\)) and top_k (default \(40\)) narrow the draw further: only the \(k\) most likely tokens, and among them only the smallest set whose probabilities add up to \(p\), can be picked. max_tokens caps the length of the reply. Every model gets the same prompts and the same settings unless set otherwise, so that differences between agents come from the models. The same temperature does not make two models equally random, though: it reshapes each model’s own word probabilities, so it treats them the same way, not makes them behave the same.

Sampling settings are fixed and recorded. disensa sends the temperature, top_p, top_k and a sampling seed with every request, instead of leaving any of them to the model server. Ollama and vLLM have different defaults, so a setting left to the server would make results from the two differ for a reason nobody chose. The defaults are Ollama’s, so runs match the ones made locally. They are set in the config file only (not in the lab’s setup) and saved with the run; the run view shows them under Models.

Thinking is off. Some models (e.g. qwen3) “think” before they answer: they write hidden reasoning first, then the reply. That reasoning uses up the reply budget (max_tokens), can contain braces that confuse the JSON parser, and is very slow: a 250-agent run with qwen3 among its models ran for about 20 hours and finished 2 steps. disensa switches it off with models[].think: false (the default), which is saved with the run and is part of the cache key. On Ollama this is Ollama’s own think option; on vLLM it is the chat-template flag enable_thinking of Qwen3-style models, which other models ignore. If a reply still starts with a <think>…</think> block, it is dropped before the JSON is read. Set think: true to study a model with its reasoning on.

Error handling and reproducibility

Models do not always follow the format. disensa asks for JSON mode when the provider supports it, and repairs common mistakes (text around the JSON, trailing commas). If that fails, it asks the model once more to fix its reply. If the reply is still unusable, or the provider returns an error, the run does not stop: the agent keeps its previous opinion, message and memory for that step, and the error is saved with the step so it can be counted and inspected. The belief must be a finite number: NaN, true or "a lot" count as failed replies. A number outside \([-2, 2]\) is clipped to the nearest end, and both the clipping and the number the model gave are saved. A missing message or memory also keeps the previous one. The one case with nothing to keep is step 0: an agent whose first message fails has no message yet, so its neighbours cannot hear it until it says something.

A few failures are normal. Many are not, and they are easy to miss, because a failed reply keeps the opinion: a run where most calls fail looks like a run of very stubborn agents. So a run stops when more than max_error_rate of the replies of one step fail (default \(20\%\), step 0 included). It is marked failed with the reason, e.g. “step 3: 47/50 replies failed (provider: connection refused)”, every finished step is kept, and disensa run exits with an error. How many replies failed, and why, is in the run report.

Every reply is cached on disk under its exact request: the model, the full prompt, the sampling settings (temperature, top_p, top_k), max_tokens and the sampling seed. Running the same config again replays the same replies without calling any model, so an LLM run is reproducible once it has been run once. Changing anything in the prompt (the statement, a neighbour’s message, the memory) makes it a new request.

Measuring opinions: self-rating and scorer

There are two ways to read an LLM agent’s opinion. The self-rating is the belief the agent reports in its own reply. It is what the simulation runs on: it becomes \(x_i(t)\), the agent sees it again in its next prompt, and the metrics are computed from it. The scorer is a separate model that reads what the agent wrote and rates it on the same 5-point scale, the way a human reader would. Chuang et al. (2024) used a scorer of this kind (Flan-T5-XXL) and validated it against blind human ratings: three raters agreed with each other at Krippendorff’s \(\alpha = 0.81\), and the scorer matched the raters’ majority 84% of the time. Self-rating was never measured against humans.

In disensa the scorer is a measurement only. It runs after a run, on the texts in events.jsonl, and never feeds back into the simulation, so the same run can be scored by several models, or again later, without changing anything that happened. Which of the two measures the analysis relies on is decided with data: a sample of messages is rated blind by several people (Human validation), and the measure that agrees better with them is used.

disensa score runs/20261103-230240_Big_Run_s44 --model ollama_chat/qwen2.5:7b
disensa score runs/topics_core --model ollama_chat/qwen2.5:7b --field reasoning

disensa score rates every text of a run, or of every LLM run in a sweep folder: by default the message each agent shared at each step (step 0 included), or its reasoning with --field reasoning. Calls go through the same client and cache as the agents, at temperature 0, with JSON replies; --api-base points it at another server. Use a scorer that is not one of the run’s agent models: a model rating its own texts may share their blind spots, and disensa warns when it is. Use a capable one, too: in a test, qwen3:0.6b rated every message \(+2\). The validation will show whether a scorer is any good, but a quick look at its ratings first saves a round of human rating. The ratings go to scores.parquet in the run folder (Run files), and the lab shows them in the agent panel next to the self-rating. The prompt, adapted from Chuang et al.’s App. I to a community instead of a social network:

Prompt: scorer 
[system]
You rate the opinions people express. Answer only with the JSON asked for.

[user]
Here is a text written by a member of a community.
---
{text}
---
What is the author's position on this statement: "{statement}"

Rate it on a 5-point scale:
-2: strongly oppose, -1: somewhat oppose, 0: neutral, 1: somewhat support, 2: strongly support.
If the text does not show the author's position on the statement, answer "unclear".
Respond ONLY with JSON: {"score": <one of -2, -1, 0, 1, 2, or "unclear">}

“unclear” is allowed so that a text taking no position is not forced to count as neutral. It is stored as an empty score with no error; a reply that is not on the scale is stored as an error.

Human validation

To decide between the self-rating and the scorer, a sample of messages is rated by several people who know nothing about the run, and both measures are compared with them (the protocol Chuang et al. used for their classifier, App. M, applied to both measures).

disensa validation export runs/topics_core --n 100 --seed 0 --out validation/topics_core
# send sample.csv and INSTRUCTIONS.md to each rater; collect ratings_<name>.csv
disensa validation report validation/topics_core

Export samples messages from the given runs or sweep folders, stratified by self-rated level: each self-rating is rounded to \(-2, \dots, 2\) and the levels are sampled as equally as possible (a level with too few messages gives its share to the others), so that strong and weak positions on both sides are all tested, not just the most common one. Only messages from step 1 on whose reply was used are sampled: at step 0 the opinion is given to the agent, and a failed reply repeats an older message. The sample is shuffled across runs and topics. It writes three files: sample.csv (item_id, statement, message and an empty rating), which is all a rater sees; key.csv, which links each item to its run, step, agent, model, self-rating and scorer ratings and is never given to the raters; and INSTRUCTIONS.md. For each message the rater answers “What is the author’s position on this statement?” with one of the five levels (or unclear), rating only the text, alone, without discussing it with the others.

Report reads every ratings_<rater>.csv (a copy of sample.csv with rating filled in) and writes report.json and report.md:

  • how much the raters agree with each other: Krippendorff’s \(\alpha\) with the ordinal metric, which counts a \(1\) against a \(2\) as a smaller disagreement than a \(-2\) against a \(2\) and handles missing ratings. \(\alpha = 1\) is perfect agreement, \(0\) is chance; Chuang et al.’s raters reached \(0.81\);
  • the raters’ majority rating of each item: the level more than half of them gave, or else their median (a median halfway between two levels goes toward \(0\));
  • for the self-rating and for each scorer: how often it matches the majority exactly, how often it is within one level, the mean absolute difference, and a confusion matrix (rows: the raters, columns: the measure).

The measure that agrees better with the raters is the one the analysis relies on; reporting both is also possible. Since the scorer never changes a run, nothing has to be rerun whichever one wins.

Initial opinions

Before the first step, every agent gets a starting opinion \(x_i(0)\) on the scale from \(-2\) (strongly oppose) to \(+2\) (strongly support), with \(0\) as neutral. Together they form \(x(0)\), the input to every rule. The opinions are drawn at random from a distribution chosen in the config, once per run, from the run’s seed (Seeds and replicates).

Distributions

DistributionDrawWhat you get
uniform\(x_i(0) \sim \mathcal{U}(-2, 2)\)Every opinion on the scale is equally likely. No starting leaning and no camps.
normal\(x_i(0) \sim \mathcal{N}(m, \sigma^2)\)Most agents start near \(m\). A small \(\sigma\) is close to consensus from the start; \(m \ne 0\) gives the whole group a leaning.
bimodal\(x_i(0) \sim \mathcal{N}(\pm m, \sigma^2)\), each sign with probability \(\tfrac12\)Two camps centred at \(-m\) and \(+m\), \(2m\) apart: the group is polarized from the start. The camps are only roughly equal in size, since each agent’s side is a coin flip.

\(m\) is mean and \(\sigma\) is std. For bimodal only the size of mean matters (\(-1.5\) and \(1.5\) give the same camps), and with mean: 0 it is just a normal distribution.

Clipping. A normal draw can fall outside \([-2, 2]\). Those values are set to the nearest end, so wide distributions stack agents at exactly \(\pm 2\). The default normal (\(m = 0\), \(\sigma = 1\)) clips about \(5\%\) of agents. bimodal with \(m = 1.5\), \(\sigma = 1\) clips about \(30\%\) of each camp, which puts a spike of extremists at both ends. The lab warns when more than \(10\%\) of agents would be clipped, or when the two camps overlap so much (\(\sigma \ge m\)) that they are not really two camps.

Where opinions land on the network

Opinions are given out independently of the network: agent \(i\)’s opinion does not depend on its links or its position. Neighbours are no more alike than any two agents, and hubs get opinions drawn like everyone else’s. Any group of like-minded neighbours that appears later was produced by the dynamics, not by the setup.

The network and the opinions use separate random draws from the same seed. Changing the distribution keeps the same network, so distributions can be compared on one network. Numeric and LLM runs with the same seed also start from exactly the same \(x(0)\).

Why the starting point matters

Each rule uses \(x(0)\) differently:

  • DeGroot always ends in consensus, so the distribution only decides where: the consensus value is the average of \(x(0)\) weighted by \(k_i + 1\). A group that starts with a leaning (normal with \(m \ne 0\)) ends near that leaning. On a scale-free network, the hubs’ starting opinions matter more.
  • Bounded confidence depends most on the starting point: what matters is \(\varepsilon\) compared with how spread out \(x(0)\) is. A narrow start can reach consensus with a small \(\varepsilon\); a wide or bimodal start tends to split into clusters or stay as two camps.
  • Friedkin–Johnsen uses \(x(0)\) as the innate opinions \(s\), so the starting point never goes away. The equilibrium \(x^\ast = \lambda(\lambda I + L)^{-1} s\) is fixed by \(x(0)\), the network and \(\lambda\). A polarized start leaves a polarized equilibrium, softened but not removed.
  • LLM agents receive their starting opinion as words and a number (see Initial opinion and first message). After that, nothing ties them to it: a model’s own leaning on the statement can pull it away. Chuang et al. (2024) found the initial distribution mattered less than expected: agents drifted toward the scientifically accurate view unless the prompt explicitly added confirmation bias.

All three numeric rules are weighted averages, so opinions never leave the range of \(x(0)\) (see Numeric algorithms). Whoever starts most extreme sets the limit for the whole run.

Metrics

After every step, including step 0, disensa sums up the opinions \(x(t)\) in three numbers that together measure polarization and echo chambers. They are the three metrics of Wang et al. (2025, §4.2). One looks only at the opinions; the other two also look at who is linked to whom. They are in metrics.py.

Polarization

How spread out the opinions are across the whole group: the variance of \(x\) (Chitra & Musco, 2020).

\[ P_z = \frac{1}{N} \sum_{i=1}^{N} \left( x_i - \bar{x} \right)^2, \qquad \bar{x} = \frac{1}{N} \sum_{i=1}^{N} x_i \]

It is \(0\) at consensus and largest, \(4\), when half the agents sit at \(-2\) and half at \(+2\). A uniform start gives about \(1.33\). It ignores the network: the same opinions shuffled across the agents give the same \(P_z\).

Global disagreement

How much linked agents disagree. Each agent’s local disagreement is the average squared gap to its neighbours, and the global value averages it over all agents:

\[ DG_i = \frac{1}{k_i} \sum_{j \in N(i)} (x_i - x_j)^2, \qquad DG = \frac{1}{2N} \sum_{i=1}^{N} DG_i \]

It is \(0\) when every agent agrees with all its neighbours, even if the group as a whole is split. The factor \(\tfrac12\) follows Wang et al.: with it, if opinions are placed on the network at random, \(DG\) comes out at about \(P_z\).

Neighbour correlation

How closely an agent’s opinion matches its neighbours’: the Pearson correlation between each agent’s opinion and the average opinion of its neighbours, across all agents (Cinus et al., 2022).

\[ NC = \operatorname{corr}\!\left( x_i,\ \bar{x}_{N(i)} \right), \qquad \bar{x}_{N(i)} = \frac{1}{k_i} \sum_{j \in N(i)} x_j \]

It runs from \(-1\) to \(+1\). Near \(0\), an agent’s opinion says nothing about its neighbours’, which is how every run starts (see Where opinions land on the network). Close to \(+1\), agents are surrounded by people who think like them: the signature of an echo chamber. At full consensus there is nothing left to correlate, so it is undefined and left empty.

Name. Wang et al. call it the “Normalized Clustering Index (NCI)” in §4.2 and “Neighbors Correlation” in their results table. disensa uses the second name.

Reading them together

No single metric tells the story; the combination does:

Outcome\(P_z\)\(DG\)\(NC\)
Consensusnear \(0\)near \(0\)undefined
Echo chambers: camps that agree inside and are apart from each otherhighlow, well below \(P_z\)high
Scattered disagreement, no structurehighabout \(P_z\)near \(0\)

The key comparison is \(DG\) against \(P_z\). If the group disagrees but linked agents agree, opinions have sorted themselves along the network. This is what Wang et al. observe on small-world and scale-free networks, where neighbour correlation rises sharply, and not on random ones.

Sweeps

An experiment is rarely one run: it is the same setup over several seeds, topics or parameter values. A sweep file describes all of them at once, and disensa sweep runs them one after the other.

name: topics_core

grids:
  - seed: [1, 2, 3]
    dynamics.statement:
      - "Euthanasia should be legal for terminally ill adults who clearly request it."
      - "..."
  - seed: [1, 2, 3]                  # numeric baselines on the same worlds
    dynamics:
      - {type: numeric, rule: degroot}
      - {type: numeric, rule: bounded_confidence}
    dynamics.epsilon: [0.5, 1.0]

Each grid maps settings to lists of values and stands for every combination of them (its cartesian product); the sweep is all the grids together. Settings are dotted paths into the config: seed, network.n, dynamics.statement. A value can be a whole block, such as a dynamics mapping, which replaces that block of the base; deeper settings like dynamics.epsilon are applied after it. Every combination is checked as a complete config before anything runs, so a typo stops the sweep at once instead of after hours. The same config twice is run once.

Each run is named after the sweep and the values that vary in its grid, e.g. topics_core__seed=2__statement=1; a long value appears as its position in the list (1 for the first). Runs go into runs/<sweep name>/, next to sweep.json: the list of runs with their config hash, status, folder and a summary of their run report. The lab groups them under the sweep’s name in Previous runs.

CommandWhat it does
disensa sweep <file>runs every run of the sweep, one after the other, and prints a table at the end: run, status, failure %, seconds
--dry-runlists the runs and estimates the LLM calls they will make, \(N \times (\text{steps} + 1)\) per LLM run, without running anything

Resuming. A run whose config already has a finished folder in the sweep folder is skipped, so running the same sweep again continues where it stopped. The comparison is by a hash of the config without its name, folders, cache folder and concurrency, which do not change what a run computes. A run that crashed, was cancelled or failed is run again from scratch; the LLM cache replays the replies it already got, so that part is instant. One failed run never stops the sweep: it is marked failed in sweep.json and the sweep goes on.

Sequential on purpose. On a Mac, Ollama answers one request at a time per loaded model anyway, so running several runs at once would not be faster; speed comes from max_concurrency within a run. On a cluster, a job array runs one share per GPU, each against its own vLLM server: see scripts/indaco/ in the repository, and Running on a vLLM server.

Example sweep files are in configs/sweeps/: bounded confidence over \(\varepsilon\) (numeric_bc_epsilon.yaml, 200 runs), Friedkin–Johnsen over the stubbornness (numeric_fj_stubbornness.yaml), and the topic runs with their numeric baselines (topics_core.yaml).

Which numeric rule does an LLM run resemble?

For each LLM run, every numeric rule is simulated on the run’s own world (its network and starting opinions, read from the run folder) for as many steps as the run had, over a grid of parameters: DeGroot once, bounded confidence over \(\varepsilon\) from \(0.1\) to \(4\) and \(\mu \in \{0.1, 0.25, 0.5, 0.75, 1\}\), Friedkin–Johnsen over \(\lambda\) from \(0.01\) to \(100\). Each simulation is compared with the run by four distances: the Wasserstein distance between the final opinion distributions (how much opinion mass has to move to turn one into the other), the difference in the number of clusters, the difference in drift, and the root mean square difference of the polarization curves. fits.csv has, per run, rule and distance, the best parameters and the distance there (when a range of parameters ties, the median of the range). A “nobody moves” baseline, \(x(t) = x(0)\), is scored the same way: a rule only explains a run if it beats it. The simulations use the engine’s own numeric code and take no time, so nothing is written to disk.

How agents respond to what they hear

Different local rules can give the same final picture (DeGroot and bounded confidence with a large \(\varepsilon\) both reach consensus), so the fit is checked at the level of single updates. For every LLM agent \(i\) at every step \(t \ge 1\) with at least one interaction and a reply that was used: \(d = \overline{x_j}(t-1) - x_i(t-1)\), how far the opinions of the authors it heard were from its own, and \(\Delta = x_i(t) - x_i(t-1)\), how much it moved. Binned by \(d\), the response curve shows the mean \(\Delta\) and the share of agents that moved. Each rule predicts a shape for the same inputs (the same agent, the same authors): DeGroot a straight line, \(\Delta = \tfrac{k}{k+1} d\); bounded confidence a line that drops to zero beyond \(\varepsilon\); Friedkin–Johnsen a line pulled back towards the starting opinion. The predictions use the best-fit parameters of the topic’s runs.

Self-rating or scorer. --measure chooses how LLM opinions are read in the whole analysis: self (the self-rating, the default) or a scorer’s name, once runs are scored (Measuring opinions). With a scorer, the summaries, fits, figures and response curves all use its ratings of the agents’ messages; a message it found unclear keeps the agent’s previous rating. The numeric simulations still start from the true \(x(0)\). LLM runs the scorer has not rated are skipped. So if the human validation prefers the scorer, the same runs are analysed again with --measure <scorer>, without rerunning anything.

All parameters

A run is described by a YAML config, the file passed to disensa run. The lab builds the same config from its form, and every run folder keeps it in meta.json. This section lists every parameter; the sections linked in the tables explain what they do.

A complete config

Only name, network.topology with its parameters, dynamics.type and, for LLM runs, dynamics.models are required. Everything else has a default. This config sets every parameter of an LLM run, each at its default where it has one:

name: Euthanasia, small-world
seed: 0
replicate: 0
steps: 10
output_dir: runs

network:
  topology: watts_strogatz   # erdos_renyi | watts_strogatz | barabasi_albert
  n: 50
  k: 6                       # watts_strogatz
  beta: 0.1                  # watts_strogatz
  # p: 0.12                  # erdos_renyi
  # m: 3                     # barabasi_albert

opinions:
  distribution: uniform      # uniform | normal | bimodal
  mean: 0
  std: 1

dynamics:
  type: llm
  statement: Euthanasia should be legal for terminally ill adults who clearly request it.
  models:
    - name: ollama_chat/llama3.2:3b
      weight: 1
      temperature: 0.7
      top_p: 0.9
      top_k: 40
      think: false
      api_base: null
  interactions: {min: 1, max: 5}
  memory_words: 60
  max_tokens: 400
  max_concurrency: 4
  cache_dir: .cache/llm
  max_error_rate: 0.2

For a numeric run, dynamics is instead:

dynamics:
  type: numeric
  rule: bounded_confidence   # degroot | bounded_confidence | friedkin_johnsen
  epsilon: 1.0               # bounded_confidence
  mu: 0.5                    # bounded_confidence
  stubbornness: 1.0          # friedkin_johnsen
Checks. A config is checked before the run starts. A missing parameter or a value out of range stops it with an error that names the parameter. Settings that are allowed but probably not intended, such as an Erdős–Rényi \(p\) too low for the network to be connected or \(\beta = 0\), give a warning instead, with a link to the section that explains it: in the lab next to the setting, and in the terminal before the run starts. Keys that disensa does not know are ignored, so a misspelled key silently leaves the default in place.
